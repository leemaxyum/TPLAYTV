# Hub Learn: First-Year CS / AI / ML Sequence

This route is for a beginner who wants the habits and foundations of a strong first-year student. Complete concepts in order within a phase; do not rush completion marks.

## Phase 0 — Learn how to learn
1. Use a 25-minute focus block.
2. Read one lesson, close it, and answer the retrieval prompt.
3. Check the worked answer only after trying.
4. Rate the flashcard honestly. Return when it is due.
5. Keep a tiny error log: what confused you, the correction, and one new example.

## Phase 1 — Express ideas in Python
Variables → Boolean logic → loops/invariants → functions → strings → lists → dictionaries → comprehensions → exceptions → files → modules → tests → objects.

**Exit check:** Build a command-line study tracker that reads tasks from a file, validates input, and has tests for its core functions.

## Phase 2 — Reason precisely
Logic → sets → functions/inverses → proof strategies → induction → counting → modular arithmetic → vectors → matrices → probability → expectation/variance.

**Exit check:** Explain a proof by induction, calculate conditional probability from a table, and implement a small simulation to validate an expected value.

## Phase 3 — Solve computational problems
Complexity → arrays → hash maps → sorting → binary search → recursion → stacks/queues → trees → graphs/BFS → dynamic programming.

**Exit check:** Solve ten small problems without looking up solutions first. For each, state input, output, invariant or recurrence, complexity, and test cases.

## Phase 4 — Understand real software
Bits/bytes → memory/references → processes/threads → HTTP/APIs → databases → networking/DNS → security → Git/version control → deployment basics.

**Exit check:** Build a tiny HTTP API, persist one entity in a database, and write a short threat model for it.

## Phase 5 — Think like an ML engineer
Train/validation/test → features/targets → baselines → gradient descent → classification → precision/recall → overfitting → data leakage → responsible evaluation.

**Exit check:** Train a simple classifier on a small public dataset, compare it to a baseline, and write down the failure modes and metric trade-offs.

## Pace

A sustainable baseline is five 25-minute sessions per week: three new concepts, one problem session, and one spaced-review session. Every fourth week should be consolidation: revisit weak flashcards, repair one project, and explain one concept aloud.

## What not to do

- Do not copy solutions before you have struggled productively for 15–20 minutes.
- Do not interpret a quiz score as mastery without explaining or applying the idea.
- Do not train or evaluate models on data that leaks the answer.
- Do not skip tests and error cases because a demo happened to run once.
